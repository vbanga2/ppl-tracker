## 2. Built

- **Seed versioning + live migration** — `SEED_VERSION = 2` constant in `repo.ts`. A `meta` table was added to Dexie (schema version 2, non-destructive upgrade). On every app start, `ensureSeedCurrent()` reads `meta.seedVersion`; if it is lower than the constant, the migration runs atomically inside a Dexie transaction and writes the new version on completion.

  **Matching logic:** Each old exercise's ID has its `ex-` prefix stripped to derive a key (e.g. `ex-bench` → `bench`). That key is matched against `imageKey` on the new seed exercises. Matched exercises (bench, ohp, dips, pullup, squat) are updated in-place — the exercise row keeps its old ID, so all setLogs remain attached. Blocks for matched exercises are reconciled by `orderIndex`: matching slots are updated in-place (preserving `blockId` → setLogs stay valid), new slots are inserted, slots that no longer exist in the new seed are soft-deleted.

  Unmatched old exercises (face pull, hammer curl, lateral raise, tricep pushdown, barbell curl, RDL, leg press, leg curl, and the old deadlift/row/calf-raise with different IDs) are soft-deleted along with their blocks. Their setLogs are **not deleted** — they remain in IndexedDB pointing at the now-soft-deleted blocks.

  New exercises with no old counterpart (incline, cgbp, sidefly, reardelt, dl, shrug, row, calf, hlr, crunch) are inserted fresh.

  **Fresh install:** if the DB has no exercises at all, the migration inserts everything from scratch — same result as the old `seedPlanIfEmpty`, now with the version stamp.

- **Dexie schema version 2** — adds `meta: 'key'` table only; all other tables are unchanged. Existing Dexie v1 databases upgrade transparently.



- **Exercise artwork** — 15 PNGs extracted from the plan PDF are now at `src/assets/exercises/`. `src/assets/exercises/index.ts` imports each one via Vite so missing keys are compile errors. The card row shows a 40×40 thumbnail; the expanded card shows the full illustration on a white background.

- **Seed data replaced** — `src/domain/plan.ts` now seeds the owner's actual 15 exercises (ohp, bench, incline, cgbp, sidefly, reardelt, dips, dl, shrug, row, pullup, squat, calf, hlr, crunch) with correct `orderIndex`, `incrementLb`, `isBodyweight`, muscle strings, formText, noteText, and video URLs straight from `plan-content.ts`. The old placeholder exercises (face pull, hammer curl, leg press, etc.) are gone.

- **`plan-content.ts` committed** — `src/domain/plan-content.ts` is the authoritative record of what came from the owner's PDF. Video URLs are untouched from the PDF annotations.

- **Exercise card redesign** — Expanded card shows: full illustration (white bg), BlockLogger prescription blocks, "Watch form" button opening `videoUrl` in a new tab, "Alternative" button when `altVideoUrl` is present (reardelt only), amber callout for `noteText`, Main/Syn/Stab muscle rows, form cues. `reardelt` shows both buttons. `calf` has no video URL so no button renders. Instagram link (crunch) gets the same neutral "Watch form" label.

- **User-overridable videoUrl** — `altVideoUrl` field added to `DbExercise` interface and domain `Exercise` type. Existing Dexie version 1 schema is forward-compatible (non-indexed field, stored transparently). User can update `videoUrl` via any future settings UI; the seeded value is the default, not a lock.

- **Cardio logging** — `CardioLogger` component appears at the bottom of each workout session:
  - Push: optional, logs minutes + distance as `kind: 'other'`

  - Legs: treadmill, logs minutes + distance as `kind: 'treadmill'`
  - Writes to `cardioLog` table. Replaces itself with "Cardio logged ✓" after saving.

## 3. Deviations

- **`altVideoUrl` not in original `DbExercise` schema** — Added to the TypeScript interface and domain `Exercise` type. Dexie stores it transparently; no version bump needed since it is not an indexed field.

- **Seed data is a full replacement** — The old placeholder exercises (incline DB press, face pull, hammer curl, barbell curl, leg press, RDL, lying leg curl, lateral raise, tricep pushdown) are removed. If any existing user data referenced those exercise IDs (`ex-incline-db`, `ex-face-pull`, etc.) it will be orphaned. This is a known trade-off; the owner had no real logged data at the time of this migration.

- **Cardio not shown in session history** — The task says "show it in session history." Session history display lives in `ProgressPage.tsx` which was not in scope for this milestone. The data is stored; surfacing it is deferred to a future milestone.

- **Incline strength block is derived at 0.8× bench** — The noteText says "load: 0.8 x flat bench power." Implemented as `deriveFromBlockId: 'blk-bench-main', deriveMultiplier: 0.8`. This matches the task note exactly.

- **Shrug block is derived at 1.0× deadlift** — The CLAUDE.md required test comment reads "shrug = deadlift strength load." Implemented as `deriveFromBlockId: 'blk-dl-main', deriveMultiplier: 1.0`.

## 4. Not built

- **What happens to unmatched logs** — Set logs for the 10 old placeholder exercises (face pull, hammer curl, lateral raise, tricep pushdown, barbell curl, RDL, leg press, leg curl, and the M1-named deadlift and row) are kept in `setLogs` unchanged. Their parent blocks and exercises are soft-deleted so they will not appear in the active exercise list or progression suggestions. The data is intact in IndexedDB and could be surfaced by a future history/export screen that queries without the `deletedAt` filter. Nothing is destroyed.

- **Cardio in session history** — `ProgressPage.tsx` does not yet surface `cardioLog` rows alongside workout history.

- **Video URL per-exercise override UI** — The schema and seed support it (`videoUrl` is a mutable field), but there is no settings UI to change it. That belongs in a future exercise-edit screen.

- **Crunch progressive rep counting** — The plan says "adding one rep every session." The block has `repLow: 10, repHigh: null` (AMRAP). Automatic cross-session rep counting would require domain logic similar to sprint set progression; deferred.

## 5. Weak spots

- **iOS icon cache** — iOS aggressively caches the home screen icon. The owner will likely need to delete the existing home screen shortcut and re-add from Safari to see the new icon. This is documented in Owner Actions.

- **Cardio saved once per session** — The `CardioLogger` checks `getCardioForSession` on mount; if any cardio row exists it shows "Cardio logged." If the user logs two entries in one session (e.g., refreshes and re-logs), both are stored and the component shows "logged" on first load. No deletion UI exists.

- **`crunch` increment is 0** — The stepper step defaults to 0 for crunch (bodyweight burnout, no weight). The `Stepper` component with `step=0` would be broken. **However**, `crunch` is `isBodyweight: true` and `incrementLb: 0`, and `BlockLogger` uses `exercise.incrementLb` as the stepper step. A step of 0 in `Stepper` would cause the ± buttons to do nothing; the user can still type a value. This is not a crash but is worth fixing in a future iteration by clamping step to at least 0.5 for isBodyweight exercises, or hiding the weight stepper entirely.
